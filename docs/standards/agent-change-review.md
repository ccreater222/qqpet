# Agent 变更审查

> 结论：审查不靠“看起来没问题”，而靠可执行证据。任何变更在合并前必须逐条检查八条不变量、跑完受影响门禁、排除红旗；重大变更还必须由未参与实现的 agent 独立验证。证据缺失时默认拒绝，而不是默认放行。

## 1. 适用范围

- 所有 agent 提交的功能、修复、重构、配置、脚本、CI 与文档变更。
- 小变更可只跑相关项并抽查；重大变更（按 `docs/standards/change-management.md` 分级）必须完整执行本文件。
- 审查者不得是本次实现的作者；作者可以提供说明，但不能给自己签字。

## 2. 可执行不变量

| # | 不变量 | 判定问题 | 可执行证据 | 常见违规 |
|---|---|---|---|---|
| 1 | 单一事实源 | 同一规则/常量/契约是否只在一处定义？ | `grep` 重复定义；检查 `src/shared/**`、`server/src/**` 与文档是否互相复制 | preload 与 renderer 各写一份命令表；文档抄两份协议字段 |
| 2 | 失败关闭 | 缺配置、缺凭据、权限不足、输入非法时是否显式失败？ | 删除/置空配置或伪造未授权 sender，运行目标测试，期望明确报错而非降级 | `catch {}` 返回空数组；缺 token 时自动切本地模式；未授权请求返回成功 |
| 3 | 否定性证明 | 是否测试了“不应该发生”的路径？ | 运行越界、未授权、重放、过期、协议版本不符、断线重连测试 | 只测 happy path；只断言 200 不断言内容 |
| 4 | 边界处校验 | 校验是否在 IPC/WS/CLI/DB 边界执行，而不是信任上游？ | 检查 `src/main/storage-ipc.ts:23`、`src/shared/sync/protocol.ts`、`server/src/validation.ts` 等边界；构造非法输入 | 只在 UI 校验；服务端信任客户端 `observedRevision`；CLI 直接写库 |
| 5 | 不可逆操作分级 | 是否涉及发布、恢复、删除、强推、密钥轮换？ | 对照 `AGENTS.md` 的不可逆清单；确认有人类批准记录 | 自行打 tag；直接 `reset --hard`；对生产库执行 restore |
| 6 | 证据优于叙述 | 交付中的结论是否有命令、退出码、产物支撑？ | 复跑关键命令；比对证据路径与提交 revision | “已测试”“应该没问题”；证据来自旧 revision；只贴截图不贴命令 |
| 7 | 最小可逆变更 | diff 是否只做必要改动，能否单提交 revert？ | `git diff --stat`、逐文件审阅、确认无夹带；确认无生成物/无关格式化 | 顺手重构全仓库；混入多个主题；删除检查项来让 CI 变绿 |
| 8 | 任务终态 | 任务是否真正完成，或明确记录阻塞？ | 对照验收标准逐条核验；检查 `team_task_update` 终态与交付报告 | “基本完成”；未跑完门禁就标完成；阻塞原因写成“环境问题” |

审查时按编号逐条给出 `通过/不通过 + 证据`，不得只给总分。

## 3. 合并前硬门禁

按变更范围取并集；任一项失败即不得合并。

| 门禁 | 命令/检查 | 通过标准 |
|---|---|---|
| 空白错误 | `git diff --check` | 无输出，退出码 0 |
| 类型 | `npm run typecheck` | 四套 tsc 全过 |
| 兼容测试 | `npm run test:compat` | 全部通过，无 skip 掩盖 |
| 文档检查 | `npm run check:docs` | 退出码 0；无未索引文档、断链、超行数、死规则 |
| 文档同步 | `npm run check:docs:staged` | 退出码 0；`require` 规则均有文档更新 |
| 提交范围文档同步 | `npm run check:docs:range` | 退出码 0；范围内每个提交的 `require` 域都同提交更新了文档（仅合法 `Docs-Check: off — <理由>` 可豁免） |
| 构建 | `npm run build` | 成功生成主进程/preload/渲染层产物 |
| 服务端 | `npm --prefix server run typecheck`、`npm --prefix server test` | 全过；协议/DB/调度改动必须 |
| 服务端构建 | `npm --prefix server run build` | 成功；部署相关改动必须 |
| E2E | `npm run test:e2e` | 真实服务端 + 双 Electron 场景通过；IPC/同步/启动改动必须 |
| 部署冒烟 | `npm run smoke:compose` / `npm run smoke:docker` / `npm run smoke:proxy` | 按影响范围通过；部署/代理/镜像改动必须 |
| 发布验收 | `npm run gate:acceptance` | gate-summary 与 E2E/Docker/Proxy 证据均通过 |
| 范围 | `git status --short`、`git diff --stat` | 只有任务允许的文件；无生成物、凭据、调试输出 |
| 冻结资产 | `git diff -- docs/reviews` | 无输出；冻结证据未被修改 |
| 文档同步 | doc-map 与目标文档 | 行为/契约变更同提交更新；无死规则 |
| 独立验证 | 未参与实现的 agent 记录 | 重大变更必须；结论含具体证据 |

命令因环境不可用时，必须说明原因、替代验证和风险，并由人类决定是否接受；不得静默跳过。

## 4. 禁止合并红旗

出现任一红旗即拒绝合并，直到修复或获得明确的人类例外批准：

- 为了让测试通过而修改/删除断言、放宽校验、增加 skip、吞掉异常。
- 用 `DOCS_CHECK=off`、`--no-verify`、删 hook、改 doc-map 来绕过文档门禁；`check:docs:range` 的失败不得靠“下个提交补”或改动基线绕过，缺文档必须回到对应提交修复或写合法 trailer。
- 用 `DOCS_CHECK=off` 环境变量期望跳过 `check:docs:range`：range 不读该开关，只看提交信息里的 trailer。
- 缺配置/凭据时自动降级、返回空实现、伪造数据或静默切换权威来源。
- 在日志、错误信息、URL、文档、提交信息中出现真实 token、配对码、私钥、生产数据。
- 修改 `docs/reviews/**` 或在其中新增报告；把新证据写进冻结目录。
- 提交 `node_modules/`、`out/`、`dist/`、`tmp/`、运行时凭据，或无任务依据地提交原始大体积生成物。
- diff 夹带无关重构、批量格式化、调试输出、硬编码绝对路径。
- 重大变更未经独立验证，或验证者就是实现者。
- 未获批准就合并 `main`、强推、打 tag、执行数据库恢复。
- 交付结论与证据不一致，或证据来自不同 revision。

## 5. 审查者操作顺序

1. **读任务与规格**：确认批准范围、验收标准、允许的写作用域。
2. **看范围**：`git status --short`、`git diff --stat`，先排除越界与生成物。
3. **读 diff**：按文件类型检查边界校验、失败关闭、错误处理、资源释放与并发顺序。
4. **复跑证据**：先快后慢运行 §3 命令；记录退出码与关键输出，不接受转述。
5. **打否定路径**：至少构造一个非法输入、一个未授权调用、一个中断/重连场景；确认失败关闭。
6. **查文档**：核对 doc-map 命中的目标文档是否同提交更新、索引与链接是否有效。
7. **查安全**：搜索密钥模式、`docs/reviews` 变更、URL 中的 token、日志中的认证帧。
8. **给结论**：逐条不变量 + 门禁表 + 红旗 + 剩余风险；结论只能是“可合并 / 需修改 / 阻塞”。

审查输出模板：

```text
结论：可合并 | 需修改 | 阻塞
范围：<分支/提交/文件数>
不变量：1 通过；2 不通过（证据）；...
门禁：<命令> 退出码 <0/1/2>
红旗：无 | <具体项>
剩余风险：<无 | 具体项>
```

## 6. 根因分析模板

用于事故、回归、门禁失败或验收失败；写入交付报告或 `tmp/reports/`，不写入冻结证据。

```text
现象：<可观察到的错误/失败命令/退出码>
影响：<影响的平台、数据、用户路径、是否阻断发布>
时间线：<首次出现 revision/时间；发现方式；处置动作>
触发条件：<最小复现步骤；输入/环境/并发条件>
根因：<具体代码路径:行号与机制，不是“疏忽”>
为什么没被现有测试发现：<测试缺口/断言过弱/环境差异>
修复：<改动点；为什么修根因而非症状>
回归测试：<新增/加强的测试与红灯证据>
预防：<门禁、类型、断言、文档或流程调整>
证据：<命令、退出码、产物路径、revision>
```

要求：根因必须落到代码或配置机制；禁止用“偶发”“环境问题”“网络抖动”结案，除非有证据并能说明为何不会复现。
