# 生产构建 CLI 整合交付报告（Android release）

> 结论：已把 HEAD `8bd94088` 临时新增的 `scripts/build-android-release.sh` 收敛为现有 npm 构建 CLI 的正式生产入口 `npm run release:android`，本地与 CI android 作业共用同一实现；真实构建产出的 `dist/QQPet-0.20.0.apk` 已通过签名/包名/版本/证书指纹独立核验，并在 emulator-5554 安装启动。实现、测试、CI 静态接入和文档均已完成；已按用户要求合并到本地 `main`（feature `96672565`，merge `2b019eac`），未推送 `origin/main`。

## 1. 问题判断与取舍

- 仓库没有独立的构建程序；`docs/guides/quality-gates.md` 明确「根 `package.json` 的脚本即事实源」。因此“现有构建 CLI”就是 npm 脚本矩阵，生产入口应加在这里，而不是另造一套平台调度器。
- 原 shell 脚本核心功能可用（基线实跑 exit 0，产出已签名 APK），但作为构建系统的一部分不成立：未接入 `package.json`；跳过 `typecheck`；不把产物归档到 `dist/`；只检查签名材料存在、不校验 APK 签名/包名/versionName；JDK/SDK 探测夹带 macOS 路径；`apksigner | head` 依赖管道行为；无 JSON 输出；CI 仍在重复同一组命令。
- 关键取舍：不新增覆盖桌面/Harmony/iOS 的统一 `build:prod`。桌面已有 `npm run dist`，Harmony/iOS 依赖专用工具链且无法在本机完整验证；本次只把 Android 生产 release 收敛成第一类 CLI，CI 复用同一命令，避免本地/CI 漂移。

CLI 契约要点：

- `npm run release:android`：预检 → `npm run typecheck` → `QQPET_VERSION=<package version> npm run build:android-web` → `./gradlew assembleRelease` → `apksigner verify --print-certs` + `aapt2 dump badging` 校验 → 原子归档 `dist/QQPet-<version>.apk`，打印 APK 与证书 SHA-256。
- `--json`（脚本化建议 `npm run --silent ... -- --json`）：stdout 只有 JSON，子进程输出全部走 stderr；字段 `ok,target,version,apk,sha256,packageName,versionName,signer,certificateSha256`。
- `--env-file <path>` / `--no-env-file` / `--help`；默认 `$QQPET_RELEASE_ENV` 或 `~/.qqpet-release/release.env`（存在时），只补未设置变量，只打印路径。
- 任一预检失败在长构建前 exit 1；不使用未签名兜底；签名/包名/versionName/证书解析失败不归档到 `dist/`。

## 4. 未验证 / 剩余风险

1. **CI android 作业未在 GitHub Runner 实跑**：本地只做 YAML 解析（9 steps，末步上传 `dist/*.apk`）与静态审查；Linux 上 `setup-java`/预装 SDK/secrets/base64 解码需在真实 tag 流程确认。这是合并/发版前唯一关键未跑路径。
2. **Windows 本地不支持**：实现按 POSIX 处理 `./gradlew` 与归档；文档已写明走 CI/WSL，未在 Windows 验证。
3. **非 clean 构建**：Gradle 复用缓存（增量），但 typecheck、Web 构建与关键打包 task 真实执行；未跑 `./gradlew clean`。
4. **并发工作区改动进入 APK**：验证期间其他工作流修改了 `android/.../PetService.kt`、`src/android/bridge.ts`、`src/renderer/main.ts`、`src/shared/ipc.ts`、`docs/architecture/desktop-ipc-and-preload.md`、`android-overlay`/`pet-drag` 测试；本任务未触碰、未回退。因为 CLI 构建工作区源码，最终 APK 包含这些改动。**若要可复现的干净生产包，应先提交/隔离这些改动再重跑 `npm run release:android`**。
5. **`test:compat` 首跑环境性 flake**：`lan.test.mjs` 共享真实 UDP 端口，首次跑曾因环境内其他宠物节点出现而失败；隔离复跑 4/4、全量复跑通过，最终状态 1106/1104/0。不是本次改动引入，但属于仓库既有稳定性风险。
6. **env 文件是 shell 子集**：支持 `export`/引号/注释，不展开 `$`/`~`；密码含空格或 `#` 时需引号。文档已写明；当前 `~/.qqpet-release/release.env` 实测四键齐全、keystore 绝对路径存在。
7. **运行时 WebView console error**：并发 renderer 改动/既有 WebView 兼容可能产生 `r.checkVisibility is not a function`，未导致崩溃、UI 可渲染；不属于构建 CLI 判定范围，建议应用侧 owner 复核。
8. **合并状态**：已按用户要求合并到本地 `main`（feature `96672565`，merge `2b019eac`）；合并只含第 2 节文件，并发工作流改动仍在工作区未提交。未推送 `origin/main`；如需远端生效，请推送并在真实 tag/CI 上确认 android 作业。
